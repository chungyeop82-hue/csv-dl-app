## 1. 개요

### 1-1. 목적

CSV 파일을 올리면 브라우저에서 데이터 확인 → 문제 설정 → 딥러닝 학습 → 결과 확인 → 결과 내려받기까지, **한 PC 안에서 인터넷 없이** 끝낼 수 있는 웹앱을 만듭니다. 딥러닝 전문 지식이 적은 학생이 표 형태 데이터로 신경망 학습을 체험하고 결과를 과제에 활용하는 것이 목표입니다.

### 1-2. 사용자와 시나리오

사용자는 **1명**(본인 PC의 소유자)이며 로그인은 없습니다. 주된 시나리오는 다음 세 가지입니다.

| ID | 시나리오 | 성공의 모습 |
|----|----------|-------------|
| US-1 | 수업에서 받은 분류용 CSV를 올려 예측 모델을 만들고 정확도를 확인한다 | 10분 안에 업로드부터 지표 확인까지 도달 |
| US-2 | 회귀용 CSV로 모델을 만들고 제출용 ZIP(`report.pdf` 등 4종)을 내려받아 과제로 제출한다 | `exports` 폴더의 제출 ZIP 안 `report.pdf`가 한글 깨짐 없이 열림 (6-6절) |
| US-3 | 폰(360px 화면)으로 접속해 학습 진행 상황과 결과를 확인한다 | 가로 스크롤 없이 모든 핵심 정보가 읽힘 |

> US-3의 "폰 접속"은 화면 너비 대응을 뜻합니다. 서비스는 `127.0.0.1`에만 열리므로 다른 기기 접속은 지원하지 않습니다(CLAUDE.md 고정 조건). 좁은 창·브라우저 반응형 보기로 검증합니다.

### 1-3. 성공 기준 (MVP 완료 정의)

1. 분류·회귀 샘플 CSV 각 1종으로 업로드 → 학습 → 결과 확인 → 내보내기를 끊김 없이 완료한다 (AT-01, AT-02).
2. CPU만 있는 환경(M1)에서 모든 기능이 동작한다 (AT-14).
3. 어떤 오류 상황에서도 화면과 API 응답에 스택트레이스가 나타나지 않는다 (AT-10).
4. 360px 너비에서 페이지 전체 가로 스크롤이 없다 (AT-11).
5. 8GB RAM 환경에서 컨테이너가 메모리 부족으로 종료되지 않고, 발생 시 안내 후 복구한다 (AT-08, AT-09).

### 6-1-1. 이번 학기 예시 데이터셋 (참고)

이번 학기 과제에서 실제 사용할 CSV는 아래와 같은 열 구성의 공정 계측 데이터입니다. 앱의 업로드·타입 감지·전처리 로직은 특정 도메인에 종속되지 않는 범용 로직이므로, 이 예시 외의 다른 Tabular CSV(분류·회귀)도 동일하게 동작해야 합니다.

| 열 이름 | 설명(추정) | 타입 |
|---------|------------|------|
| HEAD | 장비 헤드 번호 | 범주/숫자 |
| PICK_WAFER_ROW / PICK_WAFER_COL | Pick 위치의 웨이퍼 행/열 좌표 | 숫자 |
| PLACE_WAFER_ROW / PLACE_WAFER_COL | Place 위치의 웨이퍼 행/열 좌표 | 숫자 |
| ChipSizeX / ChipSizeY | 칩 크기(X/Y) | 숫자 |
| DieGapLeft / DieGapRight / DieGapTop / DieGapBottom | 다이 간격(좌/우/상/하) | 숫자 |
| ANGLE | 배치 각도 | 숫자 |
| TargetBin | **이진 분류 타깃. 0 = Fail, 1 = Good** | 범주(이진) |

`TargetBin`은 FR-17의 자동 제안 규칙(숫자이고 고유값 10 이하 정수)에 해당하는 전형적인 **이진 분류** 타깃입니다. 회귀 시나리오 검증에는 숫자형 열(예: `ANGLE`, `ChipSizeX` 등)을 타깃으로 선택해 사용할 수 있습니다. 이 데이터는 행마다 독립적인 측정 결과이며 시간 순서에 의미를 두지 않는 **정적 Tabular 데이터**이므로, 2절의 범위 확정(시계열 제외)과 일치합니다.

| 타깃(분류) | 클래스 이름을 번호로 변환하고 매핑을 모델과 함께 저장 |
| 타깃(회귀) | 표준화 후 학습, 지표는 원래 단위로 환산해 표시 |
| 누수 방지 | 모든 통계는 **학습 세트에서만** 계산하고 검증·테스트에 적용 |
| 저장 | 전처리 정보는 모델과 함께 내보내 예측 시 그대로 재사용. 전처리 객체는 joblib 파일 하나(`preprocessor.joblib`)로 저장하고, 앱이 만든 파일만 불러옴 |
| 분할 | 70/15/15. 분류는 클래스별로 같은 비율을 유지(층화)하며 클래스당 5행이어도 검증·테스트에 각 1행 이상 배정. 시드로 재현 가능. 타깃이 결측인 행은 분할 전에 제외 |
| 수치 정리 | 숫자로 읽을 수 없는 값·무한대는 결측으로 취급. 표준편차가 0인 열은 1로 대체해 0으로 만듦. 특성은 float32 |

### 6-6. 제출 ZIP 구성 (확정)

학생은 결과 화면에서 **"과제 제출"**을 누르면 아래 4개 파일이 하나의 ZIP으로 묶여 `./exports`에 저장됩니다. 이전 버전(v0.3 이전)의 "예측 CSV + 모델 파일 + 리포트" 구성은 이번 학기 **제출 범위에서 제외**하고, 아래 4종으로 통일합니다.

| 파일 | 내용 | 형식 |
|------|------|------|
| `report.pdf` | 데이터 요약, 학습·검증 손실 곡선, 혼동행렬(분류)/예측-실제 비교·잔차(회귀), 핵심 지표(6-5절), 베이스라인 비교(6-7절), 종료 사유(완료/실패/취소/시간초과), 사용 장치, 시드 | PDF, 한글 폰트 포함(FR-40) |
| `metrics.json` | 검증·테스트 지표(6-5절) 수치, 학습 곡선 원본 수치(에포크별 손실) | JSON, UTF-8 |
| `config.json` | 타깃 열·문제 유형, 전처리 요약(6-3절), 모델 설정(프리셋·은닉층·학습률 등, 6-4절), 분할 비율, 시드 등 재현에 필요한 전체 설정 | JSON, UTF-8 |
| `environment.txt` | Python 버전, PyTorch 버전, CUDA 가용 여부, GPU 장치명(있는 경우), 실제 사용 장치(cpu/cuda), 주요 라이브러리 버전 | 텍스트, UTF-8 |

**ZIP 파일명 규칙**: `학번_데이터셋명_날짜.zip` (예: `202312345_wafer_pick_place_20260928.zip`). 학번은 시스템 정보 화면(SC-09)에서 1회 입력해 두면 이후 제출마다 재사용합니다(FR-52). 데이터셋명은 업로드한 CSV의 원본 파일명(확장자 제외, Windows 금지 문자 제거)을 사용하고, 날짜는 `YYYYMMDD` 형식(한국 표준시 기준)을 사용합니다.

> **내부 저장과의 구분**: 학습된 모델 가중치·전처리 객체는 제출 ZIP에 포함하지 않고 `/data/models`에만 보관합니다(5-5절 참고 문구와 동일).

## 8. 오류·메시지 규칙

### 8-1. 노출 금지 원칙 (고정 조건 #10)

화면, API 응답, 브라우저 콘솔, 다운로드 파일 어디에도 다음을 **절대 내보내지 않습니다**.

- 스택트레이스, 예외 클래스명, 예외 원문
- 서버·컨테이너 내부 경로, 파일 시스템 위치
- SQL 문, 테이블·컬럼 이름
- 라이브러리·프레임워크 이름과 버전이 담긴 오류 문구

**디버그 모드에서도 동일**합니다. 상세 정보는 **서버 로그에만** 기록하고, 사용자에게는 오류 코드와 요청 번호만 알려 사용자가 로그를 찾을 수 있게 합니다. 404, 500 등 기본 오류 페이지와 프레임워크 기본 응답도 같은 규칙으로 대체합니다.

### 8-2. 오류 응답 구성

모든 오류는 다음 3가지 요소로만 구성합니다.

| 요소 | 설명 |
|------|------|
| 오류 코드 | `E-<영역>-<번호>` 형식 (영역: UP 업로드, DS 데이터셋, CF 설정, JB 작업, EX 내보내기, SY 시스템) |
| 메시지 | **한국어 한 문장**에 원인과 해결법을 함께 담음 (마침표는 문장 끝에 한 번) |
| 요청 번호 | 서버 로그에서 해당 오류를 찾기 위한 짧은 식별 번호 |
